# 空间逻辑校验报告

## 坐标和空间数据

GeoJSON 使用 WGS84/EPSG:4326，位置数组按 `[经度, 纬度]`。地图中心 106.523°E、29.592°N，图层含 2 个演示面、3 个模拟巡查点、3 个演示服务点。每个要素属性与项目数据说明均标明数据为构造样例。

## 算法检查

| 校验项 | 输入/预期 | 结果 |
|---|---|---|
| 点在普通多边形内 | 内部点为 true | 通过 |
| 点在普通多边形外 | 外部点为 false | 通过 |
| 外环边界 | 边界点计入范围 | 通过 |
| 孔洞与 MultiPolygon | 孔洞内部排除，其他分部件内部纳入 | 通过 |
| Haversine 距离 | 赤道经差 1° 约 111.195 km | 通过 |
| 最近要素 | 两候选点返回较近者 | 通过 |
| 空设施集合 | 返回 null，不崩溃 | 通过 |

## 交互核验

Chromium 浏览器通过本地服务器打开工程后，初始矢量要素 8 个；关闭巡查层后减至 5，关闭公园层后减至 3，关闭服务层后减至 0；重新开启巡查层后恢复为 3，计数同步。浏览器无 JavaScript 页面异常；当时在线底图加载 20 个瓦片。

免安装 HTML 另以 `file://` 直接打开验证：初始 8 个要素，全部关闭为 0，重新开启巡查层为 3；范围 A 分析统计到 1 个模拟点，最近示意服务点距离约 0.58 km，无页面脚本异常。当前自动化运行环境的代理阻断了这次 file:// 模式下的在线瓦片请求；本地要素和分析仍能完整运行。

为解决标准瓦片服务对本地文件来源请求返回 403，底图切换为 OpenStreetMap.de 的 OSM 衍生瓦片端点。对龙溪当前视图的一张瓦片进行单次 HTTP 请求，未发送 Referer 时返回 HTTP 200；项目页面仍采用常规地图视域加载，不批量抓取瓦片。最终 HTML 需要在用户电脑网络环境中验证整屏瓦片加载情况。

这些检查只验证代码逻辑与教学构造数据，不证明真实公园边界、设施位置或风险状况。
