# 需求规格说明书

## 1. 项目背景

城市公园管理人员需要在日常巡查中快速回答两个问题：风险事件是否落在具体公园范围内，以及最近的应急服务点是否足够近。传统表格按地址检索，难以发现空间关系，也不便于答辩时复现分析过程。

本项目实现一个可离线运行的 WebGIS 原型，面向课程实训，完整展示需求到部署的工程流程。样例数据经过脱敏/构造，仅用于验证流程和空间逻辑。

## 2. 用户与场景

| 用户 | 场景 | 目标 |
|---|---|---|
| 公园管理人员 | 早班巡查前查看昨日风险事件 | 快速定位应优先复核的公园 |
| 应急调度人员 | 接到事件后核对附近服务点 | 估算最近服务点距离 |
| 课程答辩评审 | 复核空间逻辑与工程过程 | 能复现、能测试、能追溯 |

## 3. 功能需求

FR-01 页面加载 GeoJSON 数据，并展示公园面、风险事件点、应急服务点。

FR-02 支持按图层开关控制可见性。

FR-03 用户选择公园或点击公园面后，系统统计落入该公园范围的风险事件。

FR-04 系统计算公园质心到最近服务点的 Haversine 距离。

FR-05 系统依据事件数量、高严重度事件数量和服务点距离输出风险分级与解释性建议。

FR-06 页面给出数据坐标系和“样例数据”声明，避免误用为生产数据。

## 4. 非功能需求

- NFR-01 可复现：不依赖数据库和商业 GIS 软件，Node.js 18+ 即可运行。
- NFR-02 可审计：空间算法有单元测试，AI 生成内容有日志和错误案例。
- NFR-03 可演示：从启动到分析结果不超过 3 分钟。
- NFR-04 可维护：数据、算法、页面分离，后续可以替换为真实 GeoJSON 或 API。
- NFR-05 正确性优先：空间分析逻辑必须通过人工审查与边界测试。

## 5. 验收标准

1. `npm test` 全部通过。
2. `npm run validate` 检查要求的代码、文档和 PPT 文件全部存在。
3. 中央河滨公园范围内应统计到 `hazard-001`，且最近服务点为 `service-001`。
4. 风险分级包含可解释的输入和计算规则。
5. 提交包包含题目要求的代码仓库、需求/设计/测试/部署/总结文档、AI 日志、提示词、错误案例、空间逻辑校验报告和答辩 PPT。
