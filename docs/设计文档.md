# 系统设计说明书

## 1. 总体架构

```text
GeoJSON 文件
    ↓ fetch
前端状态层（公园 / 风险事件 / 服务点）
    ↓
SVG 地图渲染层  ←→  交互控制层
    ↓
空间分析模块：点面包含、质心、Haversine 距离、最近服务点、风险评分
    ↓
结果面板：风险等级、指标、解释性建议
```

## 2. 技术选型

- 前端：原生 HTML/CSS/ES Modules，减少依赖，方便课堂审阅。
- 地图：SVG 自定义投影，用于教学演示和离线可复现；生产版本应替换为 Leaflet/OpenLayers，并接入合法底图。
- 数据：GeoJSON，坐标系 WGS84 / EPSG:4326。
- 服务：Node.js 内置 `http` 模块，仅提供静态文件。
- 测试：Node 内置 `node:test` 与 `assert/strict`。

## 3. 数据模型

- `parks`：Polygon，字段 `id/name/areaHa/manager`。
- `hazards`：Point，字段 `id/type/severity/reportedAt`。
- `services`：Point，字段 `id/name/type/capacity`。

三类要素以 `layers` 分层保存。当前数据使用构造样例，实际项目应记录采集时间、数据来源、授权和质量等级。

## 4. 空间分析设计

1. 对每个公园取首个 Polygon 外环，使用射线法判断风险点是否在面内。
2. 计算公园外环顶点平均值作为教学演示用质心。
3. 使用 Haversine 公式计算质心与服务点的球面近似距离。
4. 风险分数：`事件数 × 20 + 高严重度事件数 × 15 + 最近服务点超过 2 km 时加 25`。
5. 分级：`>=70 高风险，>=40 中风险，否则低风险`。

上述规则是可审计的业务原型，不应直接视为经过主管部门确认的应急标准。

## 5. 异常与边界

- 数据加载失败：页面显示启动服务提示，不渲染空结果。
- 空数据：点面分析返回空数组，页面仍可展示公园。
- 多 Polygon：算法按多个外环分别判断。
- 点在边界：当前射线算法采用教学版边界处理，生产环境需要明确边界约定并使用经过验证的 GIS 库。
- 距离输入：统一要求 `[经度, 纬度]`，避免经纬度顺序反转。

## 6. 安全与部署边界

本原型没有用户认证、写操作和外部模型调用，不处理个人敏感数据。生产化时需要增加访问控制、日志脱敏、API 限流、数据版本和备份策略。
