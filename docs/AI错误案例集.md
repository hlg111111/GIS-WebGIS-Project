# AI 错误案例集

## 案例 1：页面根路径与脚本相对路径不一致

- 现象：服务把 `/` 映射为 `src/index.html` 内容，却仍以 `/` 为浏览器地址，导致 `./app.js`、Leaflet 和样式从根目录请求并返回 404。
- 处理：访问 `/` 时重定向到 `/src/index.html`，再用浏览器检查脚本、样式和 GeoJSON 均返回成功。
- 教训：静态服务器返回的 HTML 地址会决定所有相对 URL 的解析基准，必须做浏览器端验证。

## 案例 2：Canvas 绘图导致 DOM 选择器无法核验地图图形

- 现象：启用 Leaflet Canvas 后，地图要素不生成 `.leaflet-interactive` SVG 元素，自动化检查误判为图层未显示。
- 处理：当前少量课程要素改用 Leaflet SVG 默认渲染，并在真实浏览器中确认 8 个要素可见，逐层切换时图形数量和计数同步变化。
- 教训：测试断言需与渲染实现匹配，交互要以地图真实状态和用户可见结果共同核验。

## 案例 3：点在面算法忽略 GeoJSON 内环

- 现象：只检测外环会把多边形孔洞中的点误判为面内。
- 处理：增加孔洞和 MultiPolygon 处理及对应测试，孔洞内部排除，边界按包含处理。
- 教训：空间关系实现需覆盖 GeoJSON 几何结构，而不只验证简单矩形样例。

## 案例 4：本地 file:// 页面被标准瓦片服务拦截

- 现象：双击独立 HTML 后，OSM 标准瓦片显示 403 的“Access blocked”；本地矢量图层仍能显示。
- 原因：标准 OSM 瓦片服务器要求网页请求提供有效 Referer；本地 `file://` 页面没有常规 HTTP 网页来源标识。
- 处理：切换到 OpenStreetMap.de 提供的 OSM 衍生瓦片端点；对同一视图的一张瓦片进行无 Referer 请求，返回 HTTP 200。保持图面署名，不预下载瓦片。
- 限制：该第三方瓦片服务由捐助资源运行，依赖网络与服务方可用性；若用户网络仍不能访问该域名，在线底图依然不会出现。
