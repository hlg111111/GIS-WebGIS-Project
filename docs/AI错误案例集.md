# AI 错误案例集

| 编号 | 错误/风险 | 影响 | 发现方式 | 修复与防复发 |
|---|---|---|---|---|
| E-01 | 初稿把经纬度直接按平面欧氏距离计算，且没有说明单位 | 在地图范围增大时距离会失真 | 人工审查单位与坐标系 | 改为 Haversine，并加入 1° 经度基准测试 |
| E-02 | 初稿把 `hazards.filter(...)` 写成只按名称关联，没有点面判断 | 风险事件会错误归属公园 | 用已知样例坐标逐点复核 | 使用 `pointInFeature`，并断言中央公园只命中 hazard-001 |
| E-03 | 初稿把 GeoAI 建议写成“模型预测” | 造成能力夸大和责任边界不清 | 文档与答辩口径审查 | 改为本地规则原型，注明后续接入模型需审批 |
| E-04 | 初稿允许直接双击 HTML | `fetch` 受浏览器 file 协议限制，页面无法加载数据 | 手工启动演示失败 | 增加 Node 静态服务器和明确运行步骤 |
| E-05 | 初稿没有构造/真实数据声明 | 可能被误认为生产数据 | 提交物合规检查 | 在 README、页面 footer、需求和总结中重复披露 |
| E-06 | 初稿只测试页面渲染，没有测试空间关系 | UI 正常但空间结论可能错误 | 题目要求人工审查空间逻辑 | 新增 node:test 的 inside/outside、最近点、阈值测试 |

## 审查原则

遇到 AI 生成的 GIS 代码，先确认坐标系与单位，再确认空间谓词，最后确认异常与反例。页面能显示只是集成通过，不代表空间逻辑正确。
